# সাপাহার আমের হাট — সম্পূর্ণ ফ্রি সেটআপ (GitHub Pages + Firebase Spark)

কোনো Cloud Function নেই, Blaze প্ল্যান বা ক্রেডিট কার্ড লাগে না। গ্রাহক অর্ডার দিলে ব্রাউজার থেকে সরাসরি Firestore-এ জমা হয়; দাম ও মোট হিসাব `firestore.rules` যাচাই করে।

## ধাপ
1. **Firebase প্রজেক্ট (Spark):** console.firebase.google.com → Add project। কার্ড চাইবে না।
2. **Web app:** Project settings → Your apps → Web → config কপি করে `js/config.js`-এ বসান।
3. **Authentication:** Build → Authentication → Email/Password চালু। Users ট্যাবে নিজের Gmail ও পাসওয়ার্ড দিয়ে একজন ইউজার যোগ করুন এবং তার **User UID** কপি করুন।
4. **Firestore:** Create database (production mode)।
5. **Admin (কোডে বসানো আছে):** `firestore.rules`-এর `isAdmin()` ফাংশনে admin-এর UID ও Gmail বসানো আছে; দুটো মিললেই admin, আর কেউ নয়। অন্য কাউকে admin করতে চাইলে সেখানে তার UID ও Gmail যোগ করুন।
6. **Rules:** Firestore → Rules ট্যাবে `firestore.rules`-এর পুরো লেখা পেস্ট করে **Publish** করুন। (অথবা CLI: `firebase deploy --only firestore:rules,firestore:indexes`)
7. **Indexes:** Firestore → Indexes-এ `firestore.indexes.json` অনুযায়ী ইনডেক্স বানান, অথবা CLI দিয়ে deploy। না করলে প্রথমবার ক্লিক করলে Console-এর লিংকে এক ক্লিকে বানানো যায়।
8. **GitHub Pages:** রিপোতে সব ফাইল আপলোড → Settings → Pages → Branch `main` / root। Admin URL: `https://USERNAME.github.io/REPO/admin.html`
9. **Authorized domains:** Authentication → Settings → Authorized domains-এ `USERNAME.github.io` যোগ করুন।
10. **API key সীমাবদ্ধ:** Google Cloud Console → Credentials → Browser key-তে HTTP referrer হিসেবে `https://USERNAME.github.io/*` দিন।
11. **ডেটা:** admin.html-এ লগইন → সেটিংসে ফোন, bKash/Nagad নম্বর, ডেলিভারি চার্জ সংরক্ষণ → পণ্য ট্যাবে আম যোগ করুন।

## অর্ডার কীভাবে চলে
- **অর্ডার জমা:** গ্রাহকের ব্রাউজার `orders/SA-XXXXXXXXXX` ডকুমেন্ট লেখে। Rules মিলিয়ে দেখে: পণ্যের দাম ও নাম `products`-এর সাথে, মোট কেজি প্যাকেজের গুণিতক, ডেলিভারি চার্জ, সাবটোটাল, মোট, পেমেন্ট `pending`, পণ্য সক্রিয় কি না, অর্ডার চালু আছে কি না।
- **স্টক ফিচার নেই।** কোনো আম শেষ হলে Admin → পণ্য থেকে সেটি **নিষ্ক্রিয়** করুন; তখন তালিকা থেকে সরে যাবে এবং নতুন অর্ডারে নেওয়া হবে না।
- **সীমা:** একটি অর্ডারে সর্বোচ্চ ৬ ধরনের আম; একটি আইটেমে সর্বোচ্চ ২০০ কেজি।
- **Pending পেমেন্ট:** গ্রাহক Transaction ID দিলেও `paid` হয় না; শুধু Admin বদলাতে পারে।

## নতুন সুবিধা
- **অর্ডার ট্র্যাকিং:** হোমপেজের "অর্ডার ট্র্যাক করুন" অংশে গ্রাহক অর্ডার আইডি ও মোবাইল নম্বর দিয়ে অবস্থা দেখে। এর জন্য অর্ডারের সাথে `tracking/{orderId}` নামে একটি ছোট ডকুমেন্ট তৈরি হয় (শুধু অবস্থা, মোট, আইটেমের নাম ও ফোনের হ্যাশ; ঠিকানা বা ফোন নম্বর নেই)। Admin স্ট্যাটাস বদলালে এটিও বদলায়। এই সুবিধার আগের পুরনো অর্ডারে স্ট্যাটাস প্রথমবার বদলালে ট্র্যাকিং ডকুমেন্ট নিজে তৈরি হয়ে যায়।
- **WhatsApp:** অর্ডার সফল হলে গ্রাহক "WhatsApp-এ জানান" বাটনে আপনার সেটিংসের যোগাযোগ নম্বরে মেসেজ পাঠাতে পারে। Admin অর্ডার তালিকায় প্রতিটি অর্ডারের পাশে গ্রাহককে WhatsApp (অবস্থাসহ তৈরি মেসেজ) ও সরাসরি কল বাটন আছে।
- **প্যাকিং স্লিপ প্রিন্ট:** Admin অর্ডার তালিকায় প্রিন্ট বাটন; A5 স্লিপে প্রাপকের ঠিকানা, আইটেম, মোট এবং ক্যাশ অন ডেলিভারির প্রাপ্য টাকা থাকে।

- **ডিসকাউন্ট:** Admin → পণ্য → ফর্মে "ডিসকাউন্টের ধরন" (শতাংশ % বা টাকা/কেজি) ও পরিমাণ দিন; নিচে নতুন দামের প্রিভিউ দেখায়। গ্রাহকের কার্ডে লাল ডিসকাউন্ট ব্যাজ, কাটা মূল দাম, নতুন দাম ও সাশ্রয় দেখায় এবং কার্ট/মোট হিসাব নতুন দামে হয়। শতাংশে ভগ্নাংশ নিচের পূর্ণসংখ্যায় ধরা হয় (যেমন ৯৯৳-এর ১০% ছাড় = ৮৯৳)। শতাংশ ১–৯০ এবং টাকার ছাড় দামের কম হতে হবে। Rules অর্ডারে কার্যকর দাম মিলিয়ে দেখে।
- **রিভিউ:** গ্রাহক হোমপেজ থেকে রিভিউ দেয় (প্রথমে "অপেক্ষমাণ")। Admin → রিভিউতে **অনুমোদন** করলে তবেই সাইটে দেখায়। ভুয়া রিভিউ ঠেকাতে ৫ মিনিটে একবার সীমা ও বট-ফাঁদ আছে।
- **বিক্রির রিপোর্ট:** Admin → রিপোর্টে শেষ ৭/৩০/৯০ দিনের বিক্রি দিন বা সপ্তাহ (শনি–শুক্র) অনুযায়ী চার্টে, সাথে মোট অর্ডার, বিক্রি, কেজি, গড় অর্ডার এবং কোন আম সবচেয়ে বেশি বিক্রি হচ্ছে। বাতিল অর্ডার বাদ।
- **নতুন অর্ডারের শব্দ/ব্যাজ:** Admin পেজ খোলা থাকলে নতুন অর্ডার এলে বিপ শব্দ, টোস্ট বার্তা, "অর্ডার" মেনুতে লাল সংখ্যা ও ট্যাবের টাইটেলে সংখ্যা। অর্ডার ট্যাবে "শব্দ" বাটনে বন্ধ/চালু করা যায়। (ব্রাউজারের নিয়মে পেজে একবার ক্লিক করার পর শব্দ বাজে; পেজ বন্ধ থাকলে কাজ করে না।)
- **ইন্টারনাল নোট ও কুরিয়ার ট্র্যাকিং নম্বর:** অর্ডারের পাশে নোট (📝) ও ট্রাক (🚚) বাটন। নোট শুধু Admin দেখে; কুরিয়ার তথ্য গ্রাহকের ট্র্যাকিং পেজেও দেখায়।

## ফ্রি কোটা (Spark)
প্রতিদিন ২০,০০০ ডকুমেন্ট লেখা ও ৫০,০০০ পড়া ফ্রি। একটি অর্ডার ১টি লেখা; গ্রাহক পেজ খুললে পণ্য সংখ্যা অনুযায়ী পড়া খরচ হয়। কোটা শেষ হলে পরদিন পর্যন্ত অপেক্ষা (বিল আসে না)।

## সীমাবদ্ধতা (জানা দরকার)
- **স্প্যাম অর্ডার:** Function না থাকায় ফোন-প্রতি rate limit নেই। কেউ সঠিক ফরম্যাটে অনেক ভুয়া অর্ডার পাঠাতে পারে। প্রতিরোধ: App Check (reCAPTCHA v3, ফ্রি) চালু করে `APPCHECK_SITE_KEY` বসান; Admin-এ বাতিল করুন।
- **Telegram নোটিফিকেশন** বন্ধ (এর জন্য Function লাগত)। Admin প্যানেল নিয়মিত দেখতে হবে।
- ক্লায়েন্টে ফোন নম্বর ও ঠিকানা Firestore-এ থাকে; শুধু Admin পড়তে পারে।
- Rules টেস্ট `npm i && npm run test:rules` (Java লাগে); এখনো আসল Firebase-এ চালানো হয়নি, TESTING.md দেখুন।

## সমস্যা সমাধান
- **অর্ডারে "দাম বদলে গেছে" বার্তা:** rules deploy হয়েছে? `settings/store`-এ `packageKg` ও চার্জ সংরক্ষিত? পণ্য `active`? Console → Firestore → Rules Playground দিয়ে `create /orders/SA-ABCDEF1234` সিমুলেট করুন।
- **Admin লগইনে "অনুমতি নেই":** rules-এ বসানো UID ও Gmail লগইন করা অ্যাকাউন্টের সাথে হুবহু মেলে কি না দেখুন (ইমেইল ছোট হাতের অক্ষরে), এবং rules Publish হয়েছে কি না।
- **লোকাল টেস্ট:** `npx serve -l 5000`; Emulator: `firebase emulators:start --only firestore` ও `index.html?emulator=1`।
